# מוכנות לפיילוט: מה עובד ומה חסר

מסמך זה מסכם את מצב המערכת ומה נדרש כדי לעבור מהאקתון לפיילוט אמיתי בשטראוס.

---

## ✅ מה עובד היום

### מנוע החישוב
- חישוב נטו חודשי מדויק: מדרגות מס, ביטוח לאומי, מס בריאות, זיכוי פנסיוני — הכל מ-`rules.yaml`, אפס מספרים בקוד
- ששת העובדים לדוגמה של האתגר זהים לגיליון המארגנים עד השקל (בדיקות אוטומטיות)
- חשבון עשרוני מדויק, עיגול לשקלים שלמים רק בהצגה

### כללי המשחק
- תקציבי קבוצות (א-ד) עם בחירת רכב מהקבוצה או נמוכה ממנה
- מסלול ברוכת ילדים: 4+ ילדים עד גיל 23, חלוקת פער 50/50
- החזר חשמל: +₪250 נטו בדיוק
- ויתור על רכב לפי עיסוק, עם אחזקת רכב חייבת במס
- תקציב שלא נוצל מוצג לידיעה בלבד

### היועץ (AI Agent)
- שיחה בעברית, שואל רק מה שחסר, בארבעה שלבים
- שומר מספרים (Number Guard): כל מספר בתשובה חייב להגיע מתוצאת כלי
- חיפוש רכב במאגר רשות המסים (77,988 רשומות)
- שש כלים דטרמיניסטיים: שמירת פרטים, חיפוש רכב, קטלוג, זכאות, השוואה, שאלה לנציג

### קורא מסמכים (העלאת תלוש/חוזה)
- העובד מעלה תלוש שכר או חוזה, והמערכת מציעה את הערכים לאישור
- אופציונלי — אפשר להקליד ידנית במקום

### מסך העובד
- צ'אט + פאנל "הנתונים שלי" עם עריכה ישירה
- טבלת השוואה: היום מול חלוק הפרש והסבר
- בורר רכב בכל עמודה, חישוב מחדש בלי פנייה למודל
- ימין לשמאל, ניווט מקלדת, הכרזות לקורא מסך

### מסך הנציג
- שאלות פתוחות ונענות, טופס תשובה מובנה לכל סוג
- תשובת בחירה (עיסוק/קבוצה), סכום השתתפות עם תאריך, טקסט חופשי
- המשך אוטומטי של שיחת העובד אחרי תשובה

### תשתית
- הפעלה בפקודה אחת (`docker compose up`)
- `restart: unless-stopped` על כל השירותים — השרת חוזר אוטומטית אחרי נפילה
- יותר מ-1,100 בדיקות לשרת ו-400 לאתר, בלי רשת ובלי מפתח API
- החלפת נתונים בלי שינוי קוד: קבצי YAML + CSV

## 🔶 מה חסר לפיילוט

### אבטחה והרשאות (חובה)

| פריט | מצב | מה נדרש |
|---|---|---|
| התחברות (SSO / Active Directory) | ❌ לא קיים | עובד מזדהה דרך מערכת הארגון |
| תפקידים (עובד / נציג תחבורה / מנהל) | ❌ לא קיים | הפרדת הרשאות בין מסכים |
| יומן ביקורת | ❌ לא קיים | מי ראה ומי שינה מה, לציות |
| משתמש SQL מוגבל | ❌ רץ כ-`sa` | משתמש עם הרשאות מינימליות |
| בדיקת פרטיות מול OpenAI | ❌ לא נעשתה | הסכם עיבוד נתונים (DPA) |

### נתונים אמיתיים מידי שטראוס (חובה)

| פריט | מצב | מה נדרש |
|---|---|---|
| קטלוג רכבים אמיתי | 🟡 נתוני האתגר בלבד | קובץ YAML באותו מבנה, כולל קוד סוג רכב |
| טבלת עיסוקים אמיתית | 🟡 נתוני האתגר בלבד | קובץ YAML באותו מבנה |
| לוחות מס של שנת הפיילוט | 🟡 לוחות 2025 להמחשה | עדכון `rules.yaml` |
| אישור שיטת חישוב | 🟡 לפי כללי האתגר | שטראוס מאשרת שהנטו מחושב נכון |
| בדיקות זהב נוספות | 🟡 רק 6 עובדים | נטו מאושר של שטראוס להשוואה |

### שיפורים מומלצים

| פריט | מצב | ערך |
|---|---|---|
| חישוב מצטבר (לא רק חודשי) | ⬜ לא נבנה | דיוק גבוה יותר באמצע שנת מס |
| מדיניות שמירה ומחיקה | ⬜ לא קיים | שיחות נמחקות אחרי תקופה מוגדרת |
| אירוח בענן | 🟡 Docker Compose מקומי | Kubernetes / ECS / Azure Container Instances |
| ניטור ולוגים מרכזיים | 🟡 לוגים מקומיים בלבד | Datadog / CloudWatch / ELK |

## 🔄 תהליך המעבר

```
שלב 1: שטראוס מספקת נתונים אמיתיים
        → מחליפים קבצי YAML + CSV, לא קוד
        → מריצים בדיקות זהב על נטו מאושר

שלב 2: אבטחה
        → SSO, תפקידים, יומן ביקורת
        → הסכם עיבוד נתונים מול OpenAI

שלב 3: אירוח
        → סביבת staging לבדיקות
        → סביבת production עם ניטור

שלב 4: פיילוט מצומצם
        → קבוצת עובדים מוגבלת
        → משוב → התאמות → הרחבה
```
